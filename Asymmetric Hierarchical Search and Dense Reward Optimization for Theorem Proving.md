# Asymmetric Hierarchical Search and Dense Reward Optimization for Theorem Proving

## Abstract

Formal theorem proving in environments like Lean 4 is fundamentally bottlenecked by sparse binary rewards and combinatorial state-space explosion. Existing approaches either rely on myopic tactic-level search or computationally expensive zero-shot generation. We present a novel hierarchical Reinforcement Learning framework that models proof generation as an asymmetric AND/OR search graph, explicitly decoupling high-level structural planning from low-level tactic execution. To mitigate the sparse reward problem and frequent syntax hallucinations, we introduce an AST-guided Auto-Sorrifier. This environment-integrated patching mechanism converts syntactically invalid generations into compiling partial proofs, yielding continuous, dense reward signals for RL training. Furthermore, we optimize the policy using Group Relative Policy Optimization (GRPO) augmented with a dependency-aware credit assignment mechanism. By tracing the Lean 4 kernel’s formal dependency graph, our system provides precise, bottom-up structural rewards that penalize logical hallucinations and unused subgoals. Finally, by asymmetrically allocating the search budget to prioritize tactic resolution over structural branching, our approach maximizes parallel rollout throughput and strictly bounds tree expansion, significantly improving the sample efficiency of RL-driven theorem provers.

# 1 Introduction

Automated theorem proving in formal environments like Lean 4 requires generating exact logical steps and maintaining strict syntactic correctness. Current approaches typically follow two common paradigms: exploring proof states via tactic-level search (e.g., Monte Carlo Tree Search), or prompting Large Language Models (LLMs) to generate complete proofs in a single zero-shot pass.

Both methods face significant limitations. Tactic-level search creates a massive state space and struggles with long-horizon planning, making it difficult to discover necessary intermediate lemmas. Conversely, relying on LLMs for whole-proof generation requires high inference compute and lacks the efficiency of incremental state exploration. Furthermore, optimizing these models via Reinforcement Learning (RL) is heavily constrained by the environment’s reward structure. Lean 4 provides a sparse, binary signal (e.g., 1 if the entire proof compiles, 0 otherwise). This binary outcome offers no credit for partially correct reasoning, limiting the effectiveness of RL optimization.

To address these issues, we propose an approach that explicitly separates proof search into two distinct operations: decomposing a goal into sub-hypotheses (generating proof skeletons) and resolving a goal directly (applying terminal tactics). We model this hierarchical process using an AND/OR search graph.

To overcome the sparse reward problem and handle the frequent syntax errors generated by LLMs, we introduce the AST-Guided Auto-Sorrifier. When an LLM generates a syntactically invalid step, this module parses the Abstract Syntax Tree (AST) to isolate the error and iteratively replaces the failing code with the `sorry` tactic. This mechanism allows the partial proof to compile within Lean. By doing so, it converts the binary pass/fail outcome into a dense reward signal, calculated based on the proportion of syntactically valid code remaining after patching.

We utilize this dense feedback to train a reasoning LLM using Group Relative Policy Optimization (GRPO). Because tactic execution and skeleton decomposition exhibit different evaluation characteristics, we optimize them in decoupled groups. Additionally, to discourage invalid decompositions, we apply a credit assignment mechanism that penalizes subgoals that are either logically invalid or unused in valid proof constructions.

### Main Contributions

- We introduce an AST-guided error patching mechanism that isolates syntax failures, converting sparse binary outcomes into dense reward signals for RL training.
- We propose an AND/OR search framework that explicitly separates high-level decomposition from tactic-level resolution.
- We develop a decoupled GRPO training pipeline utilizing a dependency-aware reward formulation that penalizes logical hallucinations.

# 2 Problem Formulation: The Asymmetric AND/OR Proof Graph

We formulate theorem proving in Lean 4 as a Markov Decision Process (MDP) modeled via a directed, bipartite AND/OR search graph. This graph captures the interaction between the policy (the LLM) and the formal verification environment (Lean 4 kernel). The system is defined by the tuple:

```math
\langle S, A, T, R \rangle
```

where the reward formulation \(R\) is detailed in Section 4.

## OR-nodes (States \(S\))

An OR-node corresponds to a proof state:

```math
s = (\Gamma, g) \in S
```

where:

- \(g\) is the current goal,
- \(\Gamma\) denotes the local context of available variables and hypotheses.

Since each subgoal inherits only the context valid within its own branch, two nodes sharing the same goal \(g\) but different contexts \(\Gamma\) are treated as distinct states.

An OR-node is considered solved if at least one of its outgoing actions successfully proves the goal.

The root node is the initial theorem state:

```math
s_0 = (\Gamma_0, g_0)
```

where:

- \(\Gamma_0\) contains the initial premises and variables,
- \(g_0\) is the main theorem statement.

## AND-nodes (Actions \(A\))

An AND-node corresponds to an action:

```math
a \sim \pi_\theta(\cdot | s)
```

Each action consists of a sequence of tactics rather than a single step.

To capture the hierarchical structure of mathematical reasoning, we partition the action space asymmetrically into two disjoint subsets:

```math
A = A_{tac} \cup A_{skel}
```

### Terminal Tactics

```math
a \in A_{tac}
```

Sequences of execution tactics intended to fully discharge the goal.

Example:

```lean
intro x
simp
linarith
```

### Proof Skeletons

```math
a \in A_{skel}
```

Sequences of structural steps such as:

```lean
have h1 : ...
have h2 : ...
induction n
```

An AND-node is solved only if all resulting child OR-nodes are solved.

If a terminal sequence successfully closes the goal, it produces no child nodes and is solved immediately.

## Transition Dynamics

The transition function:

```math
T(s,a)
```

is deterministically evaluated by the Lean 4 REPL.

Given a state \(s\) and tactic sequence \(a\), executing \(a\) produces a set of resulting subgoals:

```math
T(s,a)=\{s'_1,s'_2,\ldots,s'_k\}
```

### Skeleton Transitions

If a proof skeleton contains errors, the Auto-Sorrifier replaces invalid segments with `sorry`, preserving the valid structural decomposition.

The resulting subgoals are added as child OR-nodes.

### Tactic Transitions

Terminal tactics aim to fully discharge the goal.

If a sequence fails:

- the Auto-Sorrifier may patch it,
- patched versions are fed back into the model as in-context guidance,
- failed tactics do not create new search nodes.

This avoids excessive branching.

Importantly, only proof skeletons generate new subgoals. Therefore the branching factor is governed primarily by:

```math
A_{skel}
```

# 3 Policy-Guided Level-wise Rollout

Standard search algorithms sequentially expand the search tree by selecting a single node at a time. While effective, sequential expansion underutilizes the parallel architecture of modern GPUs and autoregressive LLMs.

To maximize data synthesis throughput for RL training while preventing objective mismatch between search exploration and policy optimization, we structure trajectory generation as a policy-guided level-wise rollout.

At each search depth \(d\):

1. collect all active unsolved OR-nodes,
2. sample \(K\) candidate actions for each node,
3. evaluate all in parallel.

This constructs a global batch:

```math
B_d \times K
```

allowing highly parallel inference.

## 3.1 Asymmetric Action Allocation

We asymmetrically allocate the action budget:

- 80% terminal tactics,
- 20% proof skeletons.

### Rationale

#### Terminal Tactic Space

The action space for tactic resolution is combinatorially large.

A single goal may admit many valid tactic sequences.

Thus broad sampling is necessary.

#### Proof Skeleton Space

The decomposition space is much smaller.

Most goals admit only a few viable structural strategies such as:

- induction,
- contradiction,
- case analysis.

Thus a smaller sampling budget is sufficient.

## 3.2 Complexity and Resource Management

Definitions:

- \(D\): maximum search depth,
- \(N\): node expansion limit,
- \(M\): micro-batch size,
- \(L\): token generation length,
- \(c\): Lean verification time.

### Time Complexity

At depth \(d\):

```math
O(B_d \cdot K \cdot L)
```

for inference and:

```math
O(B_d \cdot K \cdot c)
```

for Lean verification.

Overall bounded by:

```math
O(N \cdot K \cdot (L+c))
```

### Space Complexity

Structural memory:

```math
O(N \cdot K)
```

KV-cache footprint:

```math
O(M \cdot L)
```

Micro-batching decouples VRAM usage from graph breadth.

# 4 Policy Action Generation and LLM Interface

## 4.1 State Serialization

The Lean proof state is serialized into text mirroring Lean Infoview.

Example:

```text
[GOAL STATE]

x : ℕ
h : x > 0
⊢ x + 1 > 1
```

This state block forms the prompt prefix.

## 4.2 Task-Specific Prompting and Chain-of-Thought

A single policy model generates both tactics and proof skeletons.

Action types are differentiated purely through prompts.

### Terminal Tactic Prompt

```text
[TASK: TERMINAL TACTIC]
```

The model is instructed to fully solve the theorem.

### Proof Skeleton Prompt

```text
[TASK: PROOF SKELETON]
```

The model is instructed to decompose the theorem.

The policy uses chain-of-thought reasoning inside `<think>` blocks before generating Lean code.

# 5 AST-Guided Auto-Sorrifier

Language models frequently generate syntactically invalid formal proofs.

Rather than discarding invalid generations, the Auto-Sorrifier preserves valid structure by replacing erroneous regions with:

```lean
sorry
```

This enables partial proofs to compile.

## 5.1 AST Extraction and Environment Caching

Loading Lean environments repeatedly is expensive.

We therefore maintain a persistent background Lean process that caches compiled environments.

Benefits:

- rapid AST extraction,
- exact syntax localization,
- reduced verification latency.

## 5.2 Error Isolation and Iterative Patching

Procedure:

1. identify compilation error,
2. locate narrowest failing AST node,
3. replace node with `sorry`,
4. recompile,
5. repeat until successful.

Example:

```lean
have h : P := by
  invalid_tactic
```

becomes:

```lean
have h : P := by
  sorry
```

This preserves surrounding valid logic.

## 5.3 Oscillation Detection and Heuristic Fallback

Local AST modifications may induce cascading parser failures.

To guarantee termination:

- file hashes are tracked across iterations,
- repeated states trigger fallback mode.

Fallback strategy:

- locate nearest structural parent block,
- replace entire block with `sorry`,
- prune nested child commands.

This guarantees bounded computation.

# 6 Dense Reward Formulation and Credit Assignment

Standard RL propagates a single scalar reward.

Hierarchical theorem proving requires finer attribution.

We define:

1. immediate syntactic reward,
2. delayed structural reward.

---

## 6.1 Immediate Syntactic Reward

Let:

- \(T_{total}\): semantic AST nodes,
- \(T_{valid}\): valid contributing nodes.

The immediate reward:

```math
r_{env}(s,a)=
\begin{cases}
\frac{|T_{valid}|}{|T_{total}|} & |T_{total}|>0 \\
0 & \text{otherwise}
\end{cases}
```

Properties:

- perfectly valid code → reward 1,
- fully invalid code → reward 0.

---

## 6.2 Dependency-Aware Structural Reward

Subgoals are partitioned into:

### Core Dependency

```math
H_c
```

Necessary hypotheses used in the final proof.

### Benign Redundancy

```math
H_b
```

Provable but unused hypotheses.

### Malignant Hallucination

```math
H_m
```

Unprovable hallucinated subgoals.

Reward weights satisfy:

```math
W_m < W_b \le 0 < W_c = 1
```

Structural reward:

```math
r_{dep}(s,a)=
\frac{\sum_{i\in\{c,b,m\}}W_i|H_i|}{|H|}
```

This penalizes unnecessary or invalid decompositions.

---

## 6.3 Deterministic AND/OR Tree Backup

### Terminal Tactics

```math
Q(s,a)=r_{env}(s,a)+W_{solve}\cdot 1_{solved}(s,a)
```

### State Value

```math
V(s)=\max_{a\in A(s)}Q(s,a)
```

### Proof Skeletons

```math
Q(s,a)=r_{env}(s,a)
+1_{solved}(s,a)
\left(
 r_{dep}(s,a)
 + \gamma \min_{s'\in S'}V(s')
\right)
```

The `min` operator enforces strict conjunction over subgoals.

---

## 6.4 Mathematical Robustness Against Reward Hacking

A rational policy may attempt to inflate rewards by generating many redundant but valid subgoals.

The paper derives the robustness constraint:

```math
W_b \le 0
```

This guarantees redundant hypotheses cannot asymptotically increase return.

Unresolved nodes at truncation boundaries are treated as malignant failures.

This prevents stalling behavior.

# 7 RL Optimization via GRPO

The policy is optimized using Group Relative Policy Optimization.

## 7.1 Tactic Group Optimization

Terminal tactics are grouped per state.

Advantages are computed using:

```math
r_{env}
```

Groups with zero reward variance are discarded.

## 7.2 Skeleton Group Optimization

Proof skeletons are evaluated using:

```math
Q(s,a)
```

This encourages concise decompositions.

## 7.3 GRPO Objective and KL Regularization

The objective:

```math
J_{GRPO}(\theta)
=
\mathbb{E}
\left[
\frac{1}{K}
\sum_{i=1}^{K}
\left(
\min
\left(
\frac{\pi_\theta(a_i|s)}{\pi_{ref}(a_i|s)}A_i,
\operatorname{clip}
\left(
\frac{\pi_\theta(a_i|s)}{\pi_{ref}(a_i|s)},
1-\epsilon,
1+\epsilon
\right)A_i
\right)
-
\beta D_{KL}(\pi_\theta || \pi_{ref})
\right)
\right]
```

KL divergence regularization prevents policy collapse.

## B.1 Syntactic Validity as a Local Signal

Lean’s type-checker provides a strong local correctness signal.

Although syntactic validity does not imply global correctness, valid AST fragments preserve meaningful structure for RL optimization.

## B.2 Dependency Graph as Attribution Proxy

The dependency graph extracted from Lean’s kernel acts as a deterministic attribution mechanism.

While it may not reflect minimal proofs, it accurately describes the contribution structure of the generated proof instance.

## B.3 Objective Design Against Degenerate Behaviors

The non-positive constraint:

```math
W_{benign} \le 0
```

discourages reward hacking via redundant hypotheses.

## B.4 Asymmetric Action Space and Heuristic Allocation

The 80/20 split is an empirical heuristic motivated by the much larger combinatorial space of terminal tactics.

## B.5 Empirical Prerequisites for RL Optimization

The framework assumes initialization from a warm-started reasoning model such as:

- DeepSeekMath,
- Llama-3-Instruct.

This ensures non-zero baseline solve rates and sufficient reward variance for GRPO.
